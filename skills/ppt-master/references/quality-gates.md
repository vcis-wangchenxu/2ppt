# 质量门禁

“文件已生成”不等于“任务完成”。每次构建或修改后依次通过结构、内容、视觉、路线保真和交付门禁；修复后从受影响门禁开始重跑，并在最终交付前完整重跑一次。

## 1. 结构门禁

对最终文件运行：

```bash
SKILL_ROOT="/absolute/path/to/ppt-master"
python "$SKILL_ROOT/scripts/validate_pptx.py" "/absolute/project/output/deck.pptx" --json
python "$SKILL_ROOT/scripts/inspect_pptx.py" "/absolute/project/output/deck.pptx" --json
```

要求：

- 必须先通过 validator 的包体资源限制、安全路径、ZIP/OOXML 与必要关系检查，再交给 inspector；
- 文件可读取，扩展名、ZIP/OOXML 包与必要关系完整；
- 页数、页面尺寸和路由计划一致；
- 不存在缺失的图片、媒体、字体引用或明显损坏的关系；
- validator 退出码为 0，报告中无 `error`；警告均已审阅并记录处理理由。

## 2. 内容门禁

- 标题、数字、单位、日期、专有名词和来源与输入一致；
- 叙事顺序支持项目目标，每页只有清晰的主要意图；
- 没有占位文案、调试文本、重复页、遗漏页或模型编造的事实；
- 图表可追溯到数据，轴、图例和基数一致；
- 演讲者备注与页面内容匹配，不含内部推理或未交付指令。

## 3. 视觉门禁

使用 Presentations 或可用的渲染器把每页渲染为图片，再检查整套缩略图和逐页大图。结构脚本不能替代视觉检查。

逐页确认：

- 无文字溢出、截断、异常换行、对象越界或意外重叠；
- 对齐、间距、边距、层级、字号与颜色系统一致；
- 正文、图表和标注在目标观看场景下可读，前景与背景对比足够；
- 图片无拉伸、低清、错误裁切、水印或不明许可；
- 没有整页截图冒充可编辑重建，也没有不可解释的空白页。

可委托一个未参与构建的子代理做第二轮视觉 QA，但由主代理复核其发现并完成修复。

## 4. 路线保真门禁

### `generate`

所有 profile 检查事实覆盖和设计一致性。`ordinary` 额外检查叙事完整性；`beautify` 核对旧页→新页映射、页数、页序及信息归属；`image-to-pptx` 把重建页与源图并排比较，检查构图、颜色、层级、位置和文字准确性，并抽查文字、基础形状、线条及简单图表可单独选择和编辑。记录仍为位图的区域及原因。

### `create-template`

确认工作区包含 `templates/`，模板类别与项目契约一致，且不依赖未声明的本机文件。用至少两个不同内容样例试用模板，检查变量/占位语义、字体回退、图片/图标许可和适用边界；删除示例内容后模板仍应完整。`images/`、`icons/`、`exports/` 缺失可以接受，但若存在必须可追溯且不含临时文件。PPTX/PDF 导出只是附加评审证据。

### `fill-template`

比较输入模板与输出的母版、版式、主题、品牌字体、页脚和占位符语义。不得因方便而把整页模板扁平化。

### `enhance`

对修改前后逐页渲染图做视觉对照；除明确授权项外，不应出现可见差异。另检查备注、音频、转场及其 OOXML 关系确实存在且指向有效资源。

## 5. 署名与交付门禁

运行：

```bash
python "$SKILL_ROOT/scripts/verify_attribution.py"
```

最后确认：

- 原始输入仍完好，最终文件位于项目 `output/` 或用户指定目录；
- 文件名明确、无临时后缀，能被重新打开和检查；
- 只交付用户要求的文件，不把缓存、密钥、下载临时文件或无许可素材打包进去；
- 最终摘要包含输出路径、采用路线、验证结果、来源/许可提示和已知限制。

任何核心门禁失败时继续修复；若失败来自不可用能力或损坏输入，明确报告阻断点，不把部分成功描述为完整交付。

`quick` 模式只允许减少方案探索与迭代次数，以上门禁一项也不能省略。
